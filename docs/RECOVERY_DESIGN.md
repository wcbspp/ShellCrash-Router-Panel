# 恢复入口与执行边界

备份和恢复分开：创建/更新基础备份保存当前状态，恢复基础备份读取已有状态。基础区默认收起，更新前两次确认。

恢复窗口支持最新完整备份、独立基础备份、手动 WebDAV 目录和本地单组件预览。只有点击检查才读取远端，不后台扫描。未开启、未验证、有未保存参数或实际连接失败时拒绝远程读取。

服务端严格校验清单、机型、三组件大小/SHA、归档路径/链接/ELF/CRC、关键元数据和资源，独立生成计划。两机目前要求相同内核种类、版本、归档和运行二进制。K2P 在运行核心的隔离目录校验配置；AX5 先做结构与资源检查，再由事务停止代理后、写入应用前执行实际核心配置检查，避免两份 Mihomo 同时占用内存。

原生预检通过且设备开放执行时，页面取得 180 秒单次票据，经两次确认覆盖范围后只提交编号与票据。票据绑定清单和远端身份、运行状态、配置、启动文件、其他操作修订、计划和 worker SHA；过期、已使用或绑定变化均拒绝。浏览器不提供可执行计划。执行许可不随备份导出或恢复。

执行器在 `/tmp` 接管原认证任务 PID 和锁。独立 `recoveries/` 操作前回退点三组件回读成功后才暂停代理；K2P 内核用 WebDAV COPY 和有界流。失败自动回退，保留原始错误及回退结果。独立结果页在应用目录之外，断线和刷新继续查询同一任务，不自动重提。没有新增常驻服务。

不覆盖固件、LAN、Wi-Fi、SSH/WebDAV 凭据、其他插件和 ZeroTier 身份。基础点目录不因滚动备份清理而删除。旧 K2P 备份缺关键菜单必须拒绝，不能凭清单 SHA 正确判为可恢复。

本地单文件入口仅在浏览器预览格式和大小，不上传或应用；大组件应放在 WebDAV。跨版本、断电续作及全部发布矩阵没有因此实现。此前维护工具恢复/冷启动/用户客户端结果继续有效，本批新增网页结果与真实失败见 [网页恢复验收](LIVE_TEST_2026-10-16_PAGE_RESTORE.md)。

完成全部发布门槛后才生成新的已验收基础点和最终私有 RC；旧独立稳定点继续保留。
