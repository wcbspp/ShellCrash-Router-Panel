# 恢复入口与执行边界

备份和恢复分开：创建/更新基础备份保存当前状态，恢复基础备份读取已有状态。基础区默认收起，更新前两次确认。用户没有要求新增“导出已有基础版本”按钮。

恢复窗口分为来源、检查结果、覆盖范围和执行区。来源包括最新备份、独立基础备份、手动 WebDAV 目录、本地单组件。桌面窗口居中，手机占可用宽度、内容可滚动；校验值默认收起。关闭窗口不触发恢复，后台正在运行的只读检查可完成。操作采用现有认证与任务锁，不启动常驻服务。

当前已实现的流程是：

1. 选择来源：不请求文件，不扫描其他目录。
2. 点击检查：未开启、未验证或存在未保存参数时拒绝远程读取。
3. 验证清单：有界 JSON、同机型、完整三组件、合法路径和组合标识；旧基础点以索引记录的清单 SHA 校验。
4. 逐组件检查长度和 SHA256：管道流式读取，内核不落入临时归档；每个组件开始前检查内存保护和连接。
5. 显示版本、时间、用途、大小及校验值。明确尚未解包、未做内核/配置兼容性验证。保持恢复按钮禁用。

本地入口仅提供浏览器格式预检。不得把文件头、扩展名或大小合格显示成“可恢复”。当前没有自动上传或应用单文件；具体规则库应用仍要接入原有的目标内核校验、持久化版本记录及失败回退事务。

AX5 已新增电脑预检与路由器独立执行原型，实测范围见 [AX5 恢复演练](LIVE_TEST_2026-10-15_AX5_RESTORE.md)。页面执行入口仍未开放，K2P 执行器未实现。各项状态如下：

| 阶段 | 约束 | 当前状态 |
|---|---|---|
| 解包与兼容性 | 目录白名单、拒绝软硬链接/特殊文件、解压上限、ELF 机型、内核版本和配置检查 | AX5 电脑与原生流式检查已实现；三组件正例与 7 类恶意归档实机验证；K2P 待接入 |
| 操作前恢复点 | 与目标备份分开；先完成回读，空间不足则不覆盖 | AX5 独立 recoveries 目录三组件回读后才暂停服务；K2P 待实现 |
| 明确确认 | 显示目标时间、版本和具体覆盖项；两次确认且绑定本次清单 SHA、远程身份和有效期 | AX5 命令行绑定清单 SHA 与远程身份；页面确认票据及有效期待实现 |
| 独立控制面 | 恢复期间覆盖应用不能替换正在执行的恢复器；任务日志可重连查询 | AX5 独立 /tmp 执行器和结果记录已实现；电脑断线及长时锁租约待验收 |
| 完整覆盖事务 | 程序、工具、内核、资源及当时订阅/DNS/分流/节点选择/启动设置一致恢复 | AX5 同版本完整集已演练；不同内核版本及 K2P 待验收 |
| 失败回退 | 不启动不兼容候选；自动恢复操作前文件及服务，保留错误证据 | AX5 写入后受控故障自动回退通过；真实磁盘写失败、断网与断电待验收 |
| 真实验证 | AX5 可受控重启；K2P 单管理会话并遵守内存/Storage预算；不能覆盖现场旧配置冒充演练 | AX5 恢复、回退、冷启动及用户 Wi-Fi 客户端通过；本轮未操作 K2P |

不覆盖固件、LAN、Wi-Fi、SSH/WebDAV 凭据、其他插件和 ZeroTier 身份。导入的 mirror.conf 不能替换当前恢复连接身份。基础备份更新不是日常清理的一部分；旧基础目录不会因新备份生成被误删。

完成全部流程及两机恢复验收后，再将最新已验收状态打包为新基础点。原独立基础点继续保留。完整恢复和未备份升级后的冷启动不降级仍是发布门槛。
