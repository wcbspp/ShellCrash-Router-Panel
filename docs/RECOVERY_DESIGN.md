# 恢复入口与执行边界

备份和恢复分开：创建/更新基础备份保存当前状态，恢复基础备份读取已有状态。基础区默认收起，更新前两次确认。用户没有要求新增“导出已有基础版本”按钮。

恢复窗口分为来源、检查结果、覆盖范围和执行区。来源包括最新备份、独立基础备份、手动 WebDAV 目录、本地单组件。桌面窗口居中，手机占可用宽度、内容可滚动；校验值默认收起。关闭窗口不触发恢复，后台正在运行的只读检查可完成。操作采用现有认证与任务锁，不启动常驻服务。

当前已实现的流程是：

1. 选择来源：不请求文件，不扫描其他目录。
2. 点击检查：未开启、未验证或存在未保存参数时拒绝远程读取。
3. 验证清单：有界 JSON、同机型、完整三组件、合法路径和组合标识；旧基础点以索引记录的清单 SHA 校验。
4. 逐组件检查长度和 SHA256：管道流式读取，内核不落入临时归档；每个组件开始前检查内存保护和连接。
5. 显示版本、时间、用途、大小及校验值。明确尚未解包、未做内核/配置兼容性验证。保持恢复按钮禁用。

本地入口仅提供浏览器格式预检。不得把文件头、扩展名或大小合格显示成“可恢复”。当前没有自动上传或应用单文件；具体规则库应用仍要接入原有的目标内核校验、持久化版本记录及失败回退事务。

两机已有电脑预检与路由器独立执行原型，实测范围见 [AX5 恢复演练](LIVE_TEST_2026-10-15_AX5_RESTORE.md) 和 [K2P 恢复演练](LIVE_TEST_2026-10-16_K2P_RESTORE.md)。K2P 当前限制相同内核。页面执行入口仍未接通，不能将命令行结果当作页面确认按钮通过。

| 阶段 | 当前状态与限制 |
|---|---|
| 解包与兼容性 | 两机电脑检查路径、链接、体积、ELF 和元数据；AX5 另有原生归档检查；K2P 从电脑已检查集绑定长度和 SHA，缺菜单旧包拒绝 |
| 操作前恢复点 | 两机独立 recoveries 目录三组件回读后才暂停；K2P 内核使用 WebDAV COPY 和有界流 |
| 明确确认 | 两机维护工具绑定清单 SHA 与远程身份；页面两次确认、票据及有效期待实现 |
| 独立控制面 | 两机 /tmp 执行器及结果记录已实现；页面提交/结果重连、电脑断线和长任务租约待验收 |
| 完整覆盖事务 | 两机同内核恢复已实测；K2P 追加 163 个程序文件核对；跨版本未通过 |
| 失败回退 | 两机写入后受控故障回退通过；K2P 首轮缺菜单失败已记录并修正复测；真实写失败、断网和断电待验收 |
| 重启与客户端 | AX5 冷启动和用户 Wi-Fi 客户端通过；K2P 一次整机重启、同版本程序/配置/选择保持及用户 Wi-Fi 客户端通过 |

不覆盖固件、LAN、Wi-Fi、SSH/WebDAV 凭据、其他插件和 ZeroTier 身份。导入的 mirror.conf 不能替换当前恢复连接身份。基础备份更新不是日常清理的一部分；旧基础目录不会因新备份生成被误删。

完成全部流程及两机恢复验收后，再将最新已验收状态打包为新基础点。原独立基础点继续保留。完整恢复和未备份升级后的冷启动不降级仍是发布门槛。
