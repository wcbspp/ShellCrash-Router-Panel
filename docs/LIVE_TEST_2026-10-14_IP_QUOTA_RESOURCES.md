# 出口 IP、订阅余量与资源清理

2026-10-14，AX5（Mihomo 1.19.28）与 K2P（sing-box 1.12.13）。本轮只验收新增功能，不代表整个项目已达到发布条件。

## 页面行为

检测页提供 IPv4 / IPv6 出口检测按钮。请求由当前浏览器发起，使用 ipify 的固定 HTTPS 接口，不把订阅或路由器账号发送给 IP 服务。不同网站可以按规则使用不同出口；这里显示当前浏览器访问检测服务时的出口。IPv6 失败不等于 IPv4 断网。切换分流模式或默认节点后清空旧结果，避免把旧出口当成新出口。每次只发两个请求，六秒超时，无轮询；切页、隐藏或关闭页面可取消。

订阅页显示剩余 / 已用 / 总额、用量条、到期日期和查询时间。数据来自原订阅提供者的 `Subscription-Userinfo` 响应头，已用为 upload + download，和首页内核累计流量无关。只向已保存的原订阅地址发 HEAD，沿用成功加载时记录的 User-Agent；不会调用转换接口、下载或加载新配置。最多两次重定向、六秒、八 KB 响应头；使用现有内存保护阈值，低于阈值暂缓查询，无额外守护或依赖。

总额、用量或到期时间缺失时不推算；超过额度时余量显示零。失败可以重试；已读到的数据继续显示并标明“上次查询数据”，切换订阅来源后清除。浏览器刷新只读运行期缓存，不自动查询服务商；设备重启后可手动重新查询。

参考 [OpenClash 状态页源码](https://github.com/vernesong/OpenClash/blob/master/luci-app-openclash/luasrc/view/openclash/status.htm) 的出口和订阅信息布局，以及 [ipify 接口说明](https://www.ipify.org/)。未导入 OpenClash 代码或增加客户端依赖。

## 实机证据

- 两机原订阅的 HEAD 均返回 upload、download、total、expire，未发送到转换服务器。
- 两机分别在 1200 / 390 宽度真实点击“检测 IP”“查询余量”，出口与余量均显示；一轮 IP 仅两个外部请求，一次余量按钮仅一个后台查询。
- 等待现有状态轮询与刷新页面后，仍显示缓存余量，没有额外服务商查询。
- 两端无横向溢出或页面脚本错误。内核 PID 与流量模式保持不变；受保护的配置、订阅、DNS、排除条件及策略指纹不变。没有重启内核、整机或恢复远程配置。
- 首次 AX5 页面试验暴露查询预留过高，出现“内存余量不足”。最初额外预留 2 MB 已取消，这种小型读取改为使用已配置的保护阈值；最终两端查询成功。失败记录单独保留，不算成功验收。
- 离线验证覆盖无头、部分字段、重定向旧头、非法/重复数值、HTTP 认证错误、低内存、缓存来源变化、IPv6/网络失败、超额和旧数据标记。尚未在每台实机注入所有异常或验证真实到期、超额账户，矩阵为“部分通过”。

原始 JSON、敏感截图及清理前的归档保存在本地私有工作目录，不放入仓库。

## 清理结果与保留项

| 机型 | 已归档到电脑后清理 | 明确保留 |
| --- | --- | --- |
| AX5 | 七项旧改版快照，共约 473 KB 文件内容；已完成测试文件约 759 KB；已生成且不再使用的 1.43 MB 临时导出包 | 当前配置、运行内核、约 11.9 MB 当前内核恢复包、规则集、Mixbox / Entware |
| K2P | 未启用 SSR 的两份历史下载缓存，共约 620 KB；一份已完成的测试脚本 | 仍由 skipd 打开的约 2.3 MB 固件配置数据库、仍可被规则路径引用的国内 IP 表、固件原文件和卸载恢复包装 |

清理前确认 SSR 关闭、无 SSR 进程、无活动 DNS 引用；逐项归档并读取验证后再删除。没有卸载其他应用或清空服务商配置。AX5 /data 从 99% 降到约 97%，当前内核恢复包仍是最大的项目缓存。只读固件分区显示 100% 属正常挂载状态，不是可清理垃圾。

K2P 的 /etc/storage 文件同时占 RAM，并在保存时压缩写入小容量闪存。两者不能混为“空闲内存”。清理释放了文件占用，但不会解决尚未确认根因的高连接压力或 OOM；长期稳定性与完整安装、恢复、模式场景仍保留为发布前待验项。

最终 K2P Storage 包 353476 字节，小于 524288 字节上限；剩余 170812 字节。保存前检查保护阈值之外另有 6 MB 空间，保存后内核 PID 不变。skipd 的打开文件描述符已确认指向该数据库，因此不能按卸载残留删除。
