# 源码结构

`main` 是共同主分支；没有 AX5/K2P 两条长期开发分支。发布时分别构建机型包。

- `shared/ui/*.in`：公共页面、管理与监控代码；固件接口差异放在显式 `@@if ax5@@ / @@else@@ / @@end@@` 块中。普通共用代码只有一份。
- `shared/ui/*.js`、`shared/lib/`：两机字节一致的网站检测、高级面板桥接、WebDAV、参数保存、输入校验等脚本。
- `profiles/ax5/`：LuCI/Lua、procd、两内核资源与路径适配。
- `profiles/k2p/`：Padavan httpd、小分片提交、Shell/AWK、Storage 与 sing-box mini。
- `vendor/`：同一份 ShellCrash 原包、解包源码、许可、来源和校验记录。
- `tools/`：电脑端构建、下载、安装与测试。

构建器根据清单复制、渲染文件到 `build/<机型>`，不把另一机型的后端装进路由器。浏览器不解析源码条件标记，不增加运行时编译器、常驻进程或新端口。

`capabilities.json` 记录支持范围；实际允许操作仍由对应后台检查。K2P 转换入口不仅隐藏，后台在网络请求前拒绝；不依赖浏览器隐藏来保护资源预算。

迁移基线记录每个文件原始 SHA256。只有在 intentional_changes.json 记录原因并通过测试的改动可以偏离迁移基线；其他文件须逐字节一致。新增共享修改分别跑两机测试。基线只用来发现非预期变化，不代替行为与实机验证。

更新运行设备、首次干净安装和卸载恢复分别验收。不能用“页面能打开”替代配置、路由或持久化验证。

## AX5 接管方式

`transport-mode.lua` 读取 ShellCrash 的 `redir_mod`，通过原 `libs/set_config.sh` 保存；切换由现有操作锁、任务记录与 `start.sh` 服务桥执行，不启动第二个代理或守护。配置、准备的运行文件、实际启动方式分别记录；停止状态保存不会擅自启动。

Mihomo 配置生成器管理 TUN 参数，原生订阅的策略组和规则保留，但不能覆盖接管设置。混合使用 system TUN、utun、MTU 1500，关闭自动全局路由。适配防火墙只标记 LAN UDP，排除内网、DNS 与保留地址；路由器原生 UDP 不进入该链。使用固定且检查冲突的 21313 标记/策略路由表，清理仅删除自己的链、带注释的转发项和精确路由，不刷新其他路由表。

启动就绪须同时确认控制接口、接管规则与选择恢复。切换保留原流量模式，失败恢复原接管方式；前台读取实际状态，不把写入成功当成启动成功。K2P 不部署该后端，页面明确禁止混合切换。
