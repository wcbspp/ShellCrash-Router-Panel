# 面板怎么用

安装后从原路由器后台进入ShellCrash：AX5在顶部菜单，K2P在“高级设置”下。沿用路由器登录，不需要另设一套网页账号。

## 第一次使用

1. 先看顶部核心状态。AX5首次安装默认全直连，在配置页填入自己的订阅并更新；K2P安装时已准备节点，再核对实际策略组与出口。
2. 在节点页选一个策略组，再选成员。想让核心自己择优，就选自动组；想固定某个节点，再明确切换到该节点。
3. 到检测页测常用网站。只有一个目标失败时，先看它的返回类型，不用急着重启整个服务。
4. 确认配置可用后，到备份页设置WebDAV，测试、保存并创建完整备份。

## 主页面上的状态

当前出口、内核版本、运行时长、节点和连接数量、可用内存都在顶部。自启动和守护状态也在这里。启动、停止、重启作用于当前核心；手动停止会暂停自动恢复，避免刚停掉又被守护拉起。

切直连、规则或全局模式后观察新连接。已经建立的连接可能继续沿用原出口。全局TCP描述的是当前接管范围，不等于把所有UDP和IPv6都变成VPN流量。

## 节点切换与测速

策略组来自当前核心。组里还可以包含其他组，展开后再选基础节点；搜索可找全部节点，不只当前一页。Google、ChatGPT、国外AI和GitHub的常用网站分流可分别指定出口，统一保存或取消。

列表使用一次内核HTTPS测试。按需节点诊断另外分别显示Ping和HTTPS，串行执行，不会常驻后台扫全部节点。Ping测服务器ICMP往返，HTTPS测经该节点访问测试站的请求；后者包含建连和TLS握手，小设备上可能比已建立连接后的体验更慢。服务器禁ICMP时，Ping失败也不代表代理不可用。

## 网站检测

检测页查看常用网站连接与HTTPS响应。结果会区分DNS、建连、TLS、超时或HTTP返回，便于判断故障停在哪一步。它是测试请求，不是带账号浏览网页，个别网站拒绝测试请求也有可能。

## 订阅与配置

配置页管理订阅地址、User-Agent、过滤条件和下载方式。保存下次参数与把订阅更新到当前核心是不同操作，按页面任务结果确认是否已经生效。下载或校验失败保留当前配置。

AX5支持服务商直取，也可使用ShellCrash的转换方式；转换会把订阅交给所选服务。K2P只提供服务商直取和同地址兼容下载，不发送到第三方转换服务。完整JSON中的策略和规则在兼容范围内保留，本机明确设置的DNS、接管和额外域名覆盖单独保留。

## 规则与DNS

规则页查看实际生效的内核规则、策略组和连接。需要给部分网站另选出口，可用常用网站分流和额外域名覆盖；选择“跟随订阅规则”会撤销该项本地指定，让订阅继续决定。

DNS页查询和调整真实DNS / Mix及支持的Fake IP例外。页面随当前内核显示可用选项，两个内核不支持完全相同的字段。保存失败时先看返回原因，不要手工往另一种内核里套字段。

## 备份与恢复

WebDAV填好参数后先测试，成功再保存开启；改参数要重新测试。最新完整备份、独立基础备份与本机应用导出用途不同，详见[备份说明](BACKUP.md)。

恢复先检查完整组件与本机条件，再查看计划、二次确认。当前开放同机型同内核的完整恢复。连接中断后查询同一任务，别重复提交；SHA正确只说明文件完整，不等于能跨机型或跨内核使用。

## 高级面板

点击顶部“打开YACD / Yacd-Meta”。sing-box使用[YACD](https://github.com/haishanh/yacd)，Mihomo使用[Yacd-Meta](https://github.com/MetaCubeX/Yacd-meta)，共用当前核心、策略选择和连接，不启动第二套代理。

这里可以展开完整策略组、查看实时连接与规则。资源按需下载到RAM，重启后首次打开可能再次下载。打开期间轻量页暂停操作和测速；返回后重新读取核心选择。显示比例默认90%，可调整并记在浏览器里。

K2P管理时保持单一客户端。另一台设备独立打开高级面板，也仍可能修改同一个核心，不会因为本页暂停就被一起锁住。

## 内存、异常与日志

监控页看内存趋势、保护设置、清理与异常记录，运行日志看核心报错，操作记录看刚才的管理任务。先看发生了什么，再决定重试或重启；内存保护不要为了让任务继续而随意调低。

高级面板、规则库和升级都要占用额外内存。任务因保护线而暂停时，先结束不必要操作，保留日志再处理。截图或日志准备发给别人前，检查是否有订阅、密码、令牌或设备身份。
