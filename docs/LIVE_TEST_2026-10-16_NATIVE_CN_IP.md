# 原生菜单国内 IP 持久化事务

原生默认/自定义国内 IPv4 更新现与网页共用事务。K2P 调用 `manage rules`；AX5 由本机 CLI 调度同一个 `job.lua` 规则分支。两者共用任务锁、内存保护、IPv4 校验、持久文件与加载失败回退。自定义入口仅接受有界 HTTPS 来源，网页继续使用原固定来源，不新增网页任意 URL 参数。

原生数据库菜单显示持久表的日期和 SHA 前缀，避免拿上游总数据库版本冒充当前国内 IP 表版本。其他数据库入口保持原有适配流程。

| 真实设备场景 | AX5 | K2P |
|---|---|---|
| 非 HTTPS 来源拒绝 | 配置/PID/boot 不变 | 配置/PID/boot 不变 |
| HTTPS 返回非 IPv4 内容 | 已下载，由 IPv4 校验拒绝；配置/PID 不变 | 已下载，由 IPv4 校验拒绝；配置/PID 不变 |
| 默认原生入口更新 | 持久表和规则计数/日期更新，动态加载，无核心重启 | 持久表和 rules.meta 更新，保存 Storage，必要核心重启一次 |
| 自定义入口重复相同表 | 成功确认，不重启 | 成功确认，不重启 |
| 策略选择、boot ID | 保持 | 保持 |
| 原生菜单日期/SHA | 实读与持久表一致 | 实读与持久表一致 |

除国内 IP 表及其元数据外，AX5 用户配置未改。K2P 额外变化只有 `mirror.last` 的同步时间/对象种类/SHA 状态，已对照 `mirror_lib.sh` 审核；订阅、DNS、选择、启动配置保持。AX5 核心 PID 14516；K2P 从 18241 正常变为 29813。没有整机重启，之前 Wi-Fi 验证继续有效。

代码部署前保存完整私有快照，核对上一已验源码后才逐文件替换，部署期间配置/PID/boot 不变。K2P 首次电脑取快照误用了 AX5 路径，tar 拒绝后未部署任何 K2P 文件；改用 K2P 专用快照成功后继续，失败证据保留。

最终根套件 **102 项**（含新增原生入口 8 项）、AX5 **87 Python + 25 JS**、K2P **197 Python + 27 JS**通过，构建/基线/diff 检查通过。原 baseline.sha256 未修改。原始配置和日志仅在私有 `work/task-state/native-ip-20261016.private/`，不加入项目源码。

本批没有把实际同版本操作当成不同版本升级测试。读取当前已配置源得到 AX5 v1.19.28、K2P 1.12.13，均与本机相同，K2P Git blob 也相同。当前已配置源未提供不同候选，无法据此执行真实新版本未备份冷启动矩阵；版本权威、断网/同步失败、真实不同版本及其他原全量发布门槛继续保留，不能宣称最终 RC 已完成。
