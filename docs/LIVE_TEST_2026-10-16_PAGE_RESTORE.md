# AX5 / K2P 网页恢复链路验收

本批验证新增的网页链路。此前维护工具恢复、整机冷启动及用户 Wi-Fi 验证继续有效，本批没有重复整机重启。两机同内核网页恢复按钮已按原生预检条件开放。项目未公开、未推送、未发布最终 RC；旧稳定标签和独立基础点未替换。

## 实现与条件

恢复检查使用已启用、验证且实际可达的 WebDAV。服务端根据经过原生校验的清单、应用/资源元数据及当前运行核心生成独立计划；页面只提交会话编号和确认票据。两机目前都要求内核种类、版本、归档 SHA 与运行二进制一致，不支持跨版本恢复。

票据使用单调时钟，有效 180 秒、一次使用，绑定远端身份、清单 SHA、程序计划/执行器 SHA、运行 PID/boot ID、配置、启动状态及操作修订。配置或其他管理操作改变后重新检查。原生归档检查包含大小、路径/链接、ELF、gzip CRC、必需菜单及元数据。K2P 在运行核心的隔离目录做实际配置检查；AX5 先做结构与资源检查，再由独立事务停止代理后、首次写应用前运行相同核心检查，避免同时运行两份 Mihomo。

页面经两次确认后提交一次请求，独立执行器接管同一 PID 和任务锁。操作前应用、内核、资源回退点在独立 `recoveries/` 目录上传/回读成功后才停止代理。恢复进度页保存在被恢复应用之外，刷新或浏览器断线只查询结果，不重试提交。LAN、Wi-Fi、固件、SSH/WebDAV 身份及其他插件数据不属于应用恢复。

## 本批真实失败与修复

AX5 第一次新增路径检查遇到 cjson 的 `\/` 转义不兼容 Mihomo 的 YAML 读取器，在写入应用前退出并自动恢复原服务。已与正式配置写入器一致地输出 `/`，新增回归测试，并在后续真实检查中通过。

AX5 第二次实际配置检查通过，写入后启动预算把检查用的 32 MB 临时二进制与启动分配重复计数，自动回退。现检查完成即释放临时二进制，启动保留原内存阈值；后续网页正常恢复已通过。不能把两次自动回退当作正常恢复成功。

连续演练留在 RAM 的回退档案和过期预检副本曾使两机后续预检按保护阈值拒绝，服务保持运行。完整证据先保存到电脑并验证压缩读回，再精确清理重复 RAM 副本；独立 WebDAV 回退点及原恢复资料保留，没有降低内存阈值。

## 自动检查与补充修正

最终源码通过根套件 **94 项**、AX5 **87 Python + 25 JS**、K2P **197 Python + 27 JS**。原生 Lua 用例在电脑 Lua 5.1 运行时执行；缺运行时跳过不能算通过。构建、迁移基线和 diff 检查通过；原 baseline.sha256 未改。474 个源文件对本轮使用的已知凭据扫描 0 命中，不代表扫描了所有未知秘密。

新增完整备份资源门禁：冷缓存先调用已有可信高级面板安装器；K2P 补齐保存 SHA 对应的域名/原生规则。准备失败不发布缺资源的完整集。两机真实移开原高级面板缓存，由新门禁重新取得并打包资源，归档包含高级面板，K2P 另含域名和原生规则；原缓存随后还原，配置、PID 和 boot ID 前后相同，没有重启核心。

执行许可是本机能力：导出排除、恢复保持当前。两机最终真实备份归档排除许可，许可恢复回归通过。成功远端备份后释放本次 RAM 应用归档。最终代码已逐 SHA 部署，两机重新生成完整日常备份；旧基础指针未变。正式执行开关开放后，真实页面原生预检返回 ready，1200/390 布局、确认取消和 PID 不变通过；本轮没有再重复恢复。最终新完整集由电脑再次校验全部组件与归档，AX5 17 / K2P 16 个本批部署路径逐 SHA 读回一致；K2P 已保存源码与启用开关，Storage 446996 / 524288 字节。

## 保留边界

跨版本、真实断电续作/Storage 写失败、完整菜单按钮与原版本更新矩阵、原生 CN-IP 持久化入口、高连接内存与长期稳定性门槛仍须分别记录。网页链路通过不能关闭全部 P0，也不能直接宣称最终 RC 已发布。

私有证据：`work/task-state/page-execution-20261016.private/`，包含浏览器结果、完整操作前快照、各事务日志/事件、程序 SHA、配置核对、实际过期和受控故障证据。原始备份包含订阅及凭据，仅保留在私有工作区。
