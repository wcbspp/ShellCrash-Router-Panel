# 实时流量与 K2P 混合接管验证

此记录为实机增量验收，仍有未完成项，不能作为全量验收或发布许可。

## 已实现与实测

- 两机配置页都支持 Redir / 混合接管，调用 ShellCrash 设置和启动入口。K2P mini 1.12.13 在当前固件下通过 system TUN 配置校验；缺少设备、标记能力、内存或路由冲突时拒绝切换。
- K2P 从 Redir 实际应用混合一次，保留订阅配置、DNS、域名规则和三项选择器选择。内核 PID 因本次应用改变一次；后续页面测试不再重启。
- K2P 的 utun、标记路由及 UDP MARK 链已读回，收到 UDP 标记包。此证据不代替真实 Wi-Fi 客户端的 UDP 回包与应用验收。
- 首页显示内核实时上传、下载和本次启动累计流量。AX5 使用内核原生速率及累计计数；K2P 从内核累计计数差值计算速率，首次采样显示等待。总量不依赖网页是否一直打开，内核重启后重计。
- 统计为代理内核处理的流量，包含内核内的 DIRECT；绕过内核的直连不计入。后台页、配置操作和高级面板期间暂停采样，不增加常驻采集进程。
- 桌面 1200px 与手机 390px：K2P 运行页测试完成 51 组、表单测试 44 组；AX5 表单测试 54 组。脚本错误均为空，无横向溢出。这些是分组执行数，不是全部控件或场景数量。
- WebDAV 两机均实测关闭保存、错误密码测试并高亮、正确测试后重新启用。测试完恢复用户原设置，不从远端恢复。
- 两机 rule / direct / global 实际切换与读回，内核 PID 不变；测试后恢复原模式和选择器。标签及首页、域名规则、DNS 说明依据实际接管方式与流量模式变化。

## 本轮发现的问题与边界

AX5 的固件 curl 7.60 在分块传输下不执行 `--max-filesize` 上限，实际规则响应约 2.9 MB。已改为分块转发，避免 Lua 将完整 JSON 复制成整棵表；轻量规则查询在读取器中执行 1 MB 硬上限，超出明确引导高级面板，不影响已加载规则。固件 Lua 验证了超限拒绝、临时文件删除及合法数据读取。

AX5 手机布局查询阶段仍曾触发内存保护，运行页验收尚未全部完成。最新 53 组运行页记录无脚本错误，但规则/策略组/连接查询均走了保护分支，不能算正常查询通过。查询额外预留 2 MB；提示现包含实际余量与查询门槛，不能把保护当成查询正常通过，也不通过降低用户保护阈值掩盖失败。

K2P 原生国内 IP 提前绕过会阻止国内域名覆盖规则进入内核。本轮适配只在存在完整订阅模板或本地覆盖时移除 ShellCrash 自有链的该项绕过，由内核规则决定出口；基础节点配置保留原优化，局域网及必要例外不移除。针对基础/完整模板/自定义域名的隔离回归已通过，真实 LAN 路径验收继续待测。

## 尚未完成

逐菜单逐按钮剩余执行位、两机真实 LAN 的三模式与 UDP 场景、DNS/域名规则本轮完整保存及恢复、高级面板互斥、备份恢复、干净安装、重启恢复及长期稳定性仍需完成。既有测试记录继续有效，但不能替代本轮受影响功能的验收。仓库保持私有，新候选 Release 暂停发布。

## 高级面板与导出补测

K2P 桌面与 390px 高级面板打开、75%/85%/90%/100% 比例及返回共 15 组通过；原手机 iframe 宽度重复缩放导致横向溢出已修正并复测。两份本地导出均通过 gzip CRC、tar 头及路径校验。

AX5 应用备份现场余量 14,424 KB，安全打包需 20,312 KB；高级面板下载需 20,000 KB，均暂缓。已将真实预算写入页面高亮错误，原文件与运行服务保留。没有为验收清空缓存、降低保护门槛或重启内核；两个正常路径继续未通过。

AX5 后续桌面和 390px 两轮实际保护提示及返回共 5 组通过，未重启。正常导出与高级面板下载仍未通过；保护提示通过不替代正常路径通过。最终回归：根 33，AX5 58 Python + 18 JS，K2P 137 Python + 20 JS；固件 Lua 查询与流式读取隔离用例通过。
