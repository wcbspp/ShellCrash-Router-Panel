# 2026-10-15 AX5 恢复演练

AX5 已完成同版本完整集恢复、写入后受控故障自动回退、整机重启和真实 Wi-Fi 客户端验证。K2P 本轮未操作。页面恢复执行仍禁用；没有推送、发布或替换原独立基础点。

目标由演练前当前设备生成，内核为 Mihomo v1.19.28，不是用旧基础点覆盖用户新配置。电脑先检查完整三组件，另存原始私有快照。目标清单、组件、事务日志和前后指纹保存在私有工作目录；不会随源码发布。

| 检查 | 实际结果 |
|---|---|
| 原生归档验证 | 三组件正例通过；路径穿越、绝对路径、软链接、硬链接、错架构 ELF、重复项和坏 gzip CRC 共 7 类拒绝 |
| 操作前回退点 | 独立 recoveries 目录三组件上传/服务端复制、SHA 回读后才暂停服务 |
| 写入后受控失败 | 最终返回 rolledback；操作前隔离标记保留，应用/配置/资源及服务恢复 |
| 正常恢复 | 返回 done；目标未包含的隔离标记消失，目标程序及运行资源恢复 |
| 配置保护 | 10 项文件指纹、18 项策略选择、流量模式、启动集成和当前 WebDAV 身份与操作前一致；未触碰固件、LAN/Wi-Fi 或 ZeroTier 身份 |
| 内核恢复范围 | 当前包 SHA 相同，复用已验证的闪存包；运行二进制删除后重建并启动，非不同内核版本替换 |
| 整机重启 | 启动 ID 改变，内核正常自启；恢复后的选择/模式/配置及最终辅助脚本持久化 |
| 路由器业务探测 | 国内 HTTP 200、Google 204、DNS 及 ZeroTier 目标可达；ChatGPT HTTP 403 仅记网络可达 |

发现过的失败也保留记录：

- 固件没有 nohup，首次未能启动执行器，未暂停服务。改成忽略 HUP 并分离标准输入输出的原生 shell 启动方式。
- 第一次注入写后故障，文件和服务实际已回退，但健康检查遗漏内核 API 鉴权头，401 被误报为回退失败。补上保存的鉴权头和版本核对，再次实际注入同一故障，返回 rolledback，配置及服务复核通过。没有删除或改写首次失败结果。
- 冷启动后第一次 Google 请求超时；未再次重启，随后只读复测返回 204，用户两项访问正常。不能据此宣称所有单次探测从未失败。
- 最终复核发现 shell 在 if 条件内调用回退函数会抑制 errexit；补上关键清理、凭据与启动脚本写入的显式错误返回。新增存储操作失败回归，确保失败不能继续报告健康。此保护补丁已单独部署核对，不把模拟写失败算成实机闪存故障测试。

自动检查：根目录 61 项、AX5 87 Python 与 24 JavaScript 检查通过；包含备份核心哈希元数据、恢复预算、错误输入、真实本机 HTTP 鉴权/版本和回退写失败回归。构建及迁移基线检查通过；既有基线哈希未修改。

本轮恢复引起 3 次内核启动（两次故障回退、一次成功恢复），另有 1 次整机重启。没有为客户端确认追加重启。最终只更新辅助脚本和最新日常完整备份，原基础目录及索引保留。
