# 备份文件与恢复

WebDAV 默认关闭。测试先验证服务器访问和读写，保存再正式启用；更换地址、用户或密码后需要重测。取消勾选并保存关闭，保留原连接参数。关闭或未验证时不访问备份服务器。

远端保存三类记录：**最新完整应用备份**、**自动配置备份**、**基础恢复点**。备份页查询服务器的实际记录，并显示各组件的大小、版本与校验值；打开页面不会自动恢复备份。

| 备份 | 内容 | 保留方式 |
|---|---|---|
| 最新完整应用备份 | 应用安装源码、ShellCrash、订阅/DNS/分流配置、当前内核、已安装高级面板与运行规则 | 每台设备一份完整清单；新组件全部上传并回读校验后才发布新清单、清理上一份应用和运行资源对象 |
| 自动配置备份 | 配置及必要资源，不等同于完整应用 | 单独保留最新一份 |
| 基础恢复点 | 已确认可用的完整应用、内核与资源；可附项目源码快照（现有独立基础点含该文件） | 独立目录和版本标记，滚动备份不能删除它 |
| 本机应用导出 `.tar.gz` | 当前安装的应用与配置、`backup.info`、`RESTORE.txt` | 不需要启用 WebDAV；内核和临时运行资源另存 |
| 基础点完整 `.zip` | 基础点所有组件、清单及恢复说明 | 供电脑或手机留存；不是固件刷机包 |

完整远端备份使用 `format: 2` 清单，按 SHA256 引用应用、内核和运行资源压缩包，不在路由器内存中再复制一份大内核。内核和规则缓存按哈希保存，供开机恢复使用；旧完整备份的清理不会顺带删除这些缓存，也不触及 `baselines/`。`format: 1` 是旧应用/配置包记录，页面会明确标为旧格式，不能当成完整备份。

应用安装源码指实际运行的 Lua、JavaScript、Shell 等文件。基础点的 `source.tar.gz` 才是完整 Git 项目源码快照；不包含第三方内核的开发源码。应用备份可能含订阅、节点密码和本机配置，请私密保存。不含 SSH/WebDAV 凭据、整机固件、Factory 分区、其他插件数据或 ZeroTier 身份。

### 开机和更新用哪个版本

版本以**本机最后成功保存的版本、架构、SHA256 和来源记录**为准。AX5 正常更新内核后，会替换本地当前内核包和对应记录；这个当前包与独立基础恢复点不同。K2P 的程序与部分规则运行在 RAM，整机重启后需要获取记录对应的文件。

顺序是：可用的本地匹配文件 → 开启、验证且实际连接正常的 WebDAV 同版本文件 → ShellCrash 配置的同版本下载源。K2P 缺少本地包时从 WebDAV 开始；公网下载源兜底。远端基础点只有在内核 SHA256 与本机期望值相同时才能提供开机文件，不能用旧基础点的版本覆盖本机记录。找不到指定文件就提示恢复失败，保留版本记录供重试；更新成功但远端未同步时，应显示待同步。

每次远程传输先确认启用状态和参数指纹，再用带认证的 WebDAV 目录查询检查实际连接。旧的“曾验证成功”标记不代表服务器一直在线。修改地址或账号密码后要重新测试并保存；关闭或未验证时不访问远端。高级面板同样遵守这一条件。

K2P 使用同文件系统快照和受预算限制的流式压缩；客户端校验长度、SHA256 与 gzip 标识再下载。内存或持久空间不足时保留原文件并反馈，不提供截断包。旧的损坏下载不可用，必须重新导出。

### 创建和更新基础备份

备份页底部的“基础备份”默认收起。确认当前使用正常后，点击“创建基础备份”；已有备份时按钮变为“更新基础备份”，两次确认后才提交。这个操作保存当前状态，不会恢复设备。“恢复基础备份”是独立入口。先生成当前完整备份，再由 WebDAV 服务器复制成独立的基础目录，逐组件回读 SHA256，最后发布基础索引。服务器不支持 COPY 或校验失败时，保留原基础版本并报错；不会在路由器 RAM 复制一个大内核包。基础点包括实际安装的程序源码，不自动补出与当前版本不对应的开发仓库源码。

完整回退会恢复当时的应用、内核、资源及订阅、DNS、分流和启动设置，覆盖之后的修改。该操作不恢复整机固件、LAN/Wi-Fi 或 ZeroTier 身份。正常开机仍以本机最后成功安装记录为准，不能因发现基础点就自动降级。

### 文件怎么放

填写 WebDAV 根地址，例如 `https://backup.example/dav`，不要把机型目录填进根地址。程序自动分开：

```text
shellcrash-panel/
├── AX5/
│   ├── backups/              日常备份清单与应用包
│   ├── objects/              按 SHA256 保存的内核和运行资源
│   ├── baselines/            独立基础版本；滚动清理不触碰
│   └── imports/my-backup/    用户手动放入的一份完整备份
└── K2P/                      同样结构，禁止跨机型恢复
```

`imports/my-backup/` 内放 `manifest.json`、`application.tar.gz`、`core.tar.gz`、`runtime-assets.tar.gz` 及说明，保持整套和原名。每份单独一个子目录，先传完再刷新，不要把手动文件塞进自动维护的 `backups/` 或 `objects/`。页面按填写的 WebDAV 根地址计算完整路径；有未保存修改时明确标成地址预览，真实读取仍使用已保存并验证的地址。显示路径不发网络请求。恢复窗口只有点击“检查备份文件”才读取所选清单和组件，不后台扫描，不自动恢复。

新应用导出内有 `使用说明.txt`；新基础目录另有中文 `GUIDE.txt` 和 `RESTORE.txt`，解释每个文件与完整回退流程。旧包可能只有技术版 `RESTORE.txt`，不会为更新说明改写已有基础包。

### 在电脑检查完整包

使用随包提供的标准 Python 工具，无额外第三方依赖：

```sh
python3 tools/backup_bundle.py inspect 完整备份.zip --model K2P
python3 tools/backup_bundle.py pack 已下载的完整备份目录 --output K2P-完整备份.zip --model K2P
```

检查覆盖机型、组件大小与 SHA256、gzip CRC、归档路径/链接和内核 ELF 架构。工具只在电脑解包和组装，不连接或修改路由器；不会执行备份里的脚本。完整 ZIP 已压缩的组件不再二次压缩，附中文说明。不能把单独的应用导出包拼成缺少内核的假完整包，也不能覆盖已有输出 ZIP。

### 恢复窗口

“选择备份”打开恢复窗口，基础备份旁的入口会预选基础来源。支持检查最新完整备份、独立基础备份和 `imports/<备份名>/manifest.json`。手动目录名仅含字母、数字、短横线和下划线，不能填写外部 URL 或跨目录路径。

点击检查后，路由器使用当前已保存、启用且验证过的 WebDAV 设置，再检查实际连接。检查严格解析清单、核对机型，并逐个流式核对应用、内核和运行资源的字节数与 SHA256；不会在 tmpfs 暂存整个内核，也不解包执行任何备份脚本。旧基础点没有时间记录时显示“时间未记录”，不会推测时间；旧清单另外校验其基础索引中的 SHA256。附带开发源码单独列出，不作为恢复组件，也不宣称本次已校验。

本地单文件入口目前只在浏览器查看 `.txt` 国内 IPv4 表语法、`.srs` / `.mrs` 标识和 `.tar.gz` 压缩头及大小，识别明显类型错误；这不等于完整兼容性检查。文件不会上传或应用，K2P 不用原生管理页的 16 字节命令通道传整个内核包。大组件请用 WebDAV 客户端放入指定目录。

**实施状态：**窗口与只读检查已实现。确认恢复按钮保持禁用；解包兼容性校验、恢复前快照、覆盖事务和失败自动回退仍需实现与实机演练。不能将组件 SHA256 通过写成可执行恢复或恢复验收通过，也不要手动解压覆盖运行设备。全部完成后才重新生成稳定基础点和发布候选。

导出的应用包不保留运行时 JSON/配置软链接；匹配版本的安装脚本和启动钩子会重建这些链接。遇到未知软链接会停止导出并保留旧备份，避免产生不能在电脑解压或误包含其他文件的归档。

电脑升级工具另存的是升级前完整私有目录快照，用于原设备回退，与页面的可携带应用导出不同。这个快照可能含 WebDAV 凭据和运行时链接，只应保存在自己控制的电脑，不能分享或上传公开仓库。K2P 的升级前快照由电脑直接通过 SSH 获取并校验，不依赖设备上待修复的导出脚本。

K2P 开机恢复需要网络可用。内核与规则资源都按保存的 SHA256 校验；下载失败不会用不完整文件启动。首次开机未完成时，由已有的每分钟守护重试，间隔逐步增加至五分钟，成功后清理待重试状态。手动停止或关闭自启后不执行这种重试，首次启动重试与运行中崩溃分开计数。
