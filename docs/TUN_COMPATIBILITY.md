# ZeroTier/TUN 兼容适配

保护策略、配置事务和界面共用一份实现，设备差异留在适配层。支持与否取决于当前服务及安全操作能力，不按机型名称跳过保护。

- 策略与事务：`shared/lib/zerotier-compat.lua`
- 控件与请求协议：`shared/ui/manager.js.in`
- AX5 适配器：`profiles/ax5/ax5/zerotier-compat.lua`
- Padavan 适配器：`profiles/k2p/payload/starts/zerotier-compat.lua`、`zerotier-service.sh`

## 新设备要提供什么

适配器通过 `loadfile` 将运行环境和下面的能力传给共享模块：

| 字段 | 要求 |
|---|---|
| `home` / `binary` / `path` | 受支持的服务数据目录、程序和对应 `local.conf` |
| `configured_home()` | 可选，从受支持的启动配置读取数据目录 |
| `prefix` | 项目实际使用的 TUN 接口前缀 |
| `available()` | 只读检查服务与适配能力，返回布尔值 |
| `restart()` | 只重建原先运行的服务；保留身份、路由、防火墙；有明确时限 |
| `persist()` | 可选；持久化并回读校验，失败返回 false |
| `allow_missing` | 仅用于配置位于易失目录且已实现恢复的适配器 |

运行环境提供 `C`、`R`；已有固件读写、锁和 JSON 工具可以复用，共享模块也提供基础实现。配置、备份和状态均限制大小，禁止软链。共享事务负责追加、归属记录、原样撤销和失败回退，适配器不要另写一套策略。

面板核对运行中的程序和启动配置，并解析两者指向的真实目录。路径一致后，才能写入该目录下的 `local.conf`。自定义目录必须位于受支持的持久存储，且目录由 root 管理。每个自定义目录的面板状态和回退备份分别保存。多实例、临时目录或无法确认重启方式时，兼容按钮不可用。

AX5 使用 Entware 的 `S27zerotier`，支持启动脚本将 `ARGS` 明确设成 `"-d /mnt/disk/zerotier"`，路径名请用不含空格的 ASCII 字符。K2P 的原生服务仍从 `/var/lib/zerotier-one` 启动。如果该位置由设备配置指向持久目录，面板会跟随并核对实际位置。面板不会迁移目录或修改启动脚本。

## 接入现有生命周期

1. 将共享模块放进设备 manifest，适配器不复制共享源码。
2. 在代理准备阶段调用 `enforce()`；仅在就绪后调用 `finish()`，完成必要的服务重建。
3. 接入原有认证、任务锁和内存保护。状态读入口为 `ztcompatread`，控制为 `ztcompat`，只接受 `0` 或 `1`。
4. 复用监控页现有控件。未适配或缺少安全能力时显示不可用；新安装默认关闭。

服务脚本可能包含额外操作。Padavan 原生 ZeroTier 启动入口会重放固件静态路由，停止入口会删除运行目录，不能直接拿来当普通重启。当前适配器只重建经过确认的原进程，保留身份文件，并有界保存、恢复路由；不写 NVRAM，也不重建防火墙。

## 验证后再声明支持

共享测试覆盖未知字段保留、已有排除项、文件原先缺失、外部修改、锁冲突、坏 JSON、软链、保存或重建失败。固件测试还须覆盖入口不匹配、身份缺失、Storage 忙及路由保留。

真机验收包括认证后台开关、重复开启不重启、撤销还原、易失配置恢复，以及身份、节点、路由、防火墙保持。检查服务实际监听和双向访问，分别记录中继与直连。可视点击、整机重启和长期观察没有执行时应单列，不用配置文件中的“已启用”替代这些证据。

统一支持这项设置，不代表每台设备都需要开启。排查时先核对普通路由、静态网关与回程；路由错误不能靠 TUN 排除项解决。该选项调整的是 ZeroTier 选择的底层接口，不修改订阅分流、透明代理接管范围或所有 UDP 的处理。应用设置会短暂重建 ZeroTier；前缀排除也会影响其他同名前缀接口，需要按实际用途决定是否启用。
