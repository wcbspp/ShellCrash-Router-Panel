# K2P 同版本恢复验收

测试对象为当前 K2P，sing-box mini 1.12.13；用户授权继续验证，始终只用一个管理客户端。没有以旧远端基础点覆盖当前设置，AX5 本轮未恢复或重启，仅同步页面说明。以下是命令行与原生执行器结果，不能作为页面执行按钮通过的证据。

## 实际发现并修复的问题

首轮故障注入虽然返回自动回退、配置和服务检查也通过，但下一次恢复无法正常停止内核。追查发现旧应用包遗漏 `menus`、`task`，回退后原生停止入口缺少菜单依赖。此前“回退完成”不足以证明程序完整。

已从本轮操作前原机私有 Storage 快照补回 19 个菜单文件，逐个 SHA256 验证；未借用旧远端设置。备份现在包含菜单、任务及原生 provider/task 列表，并记录自启、启用状态和流量模式。电脑检查强制要求关键程序存在，缺菜单的旧包在修改设备前拒绝。

原生停止流程先删除守护任务再停止内核；这次缺依赖使其只完成前半步。已恢复原有两条任务，并添加停止失败时还原任务及启用标记的保护。该失败保护用隔离模拟验证，未再次故意破坏真实停止入口。

## 尚未通过的发布门槛

页面仍只有只读组件检查，没有恢复确认票据、有效期、独立任务提交和恢复后结果重连。不能直接解除“确认恢复”的禁用。当前 K2P 只支持同内核恢复；跨版本、断电续作、长时断网/任务租约及所有菜单业务场景也没有因此宣告通过。旧独立基础点继续保留，未自动晋升为新稳定版本，未发布新候选。

两机页面的恢复说明已同步为实际状态，“确认恢复（暂未开放）”保持禁用。AX5 本轮仅更新此说明文件，核心 PID 未变；未进行额外恢复或重启。

收尾时生成新的日常完整备份，电脑再次核对三组件及全部 163 个已安装程序文件，面板版本标记与本批源码一致；原有独立基础索引保持不变。Storage 最终保存 432750 / 524288 字节，当前核心未额外重启。冷启动后补齐高级面板再生成本次完整包，不把这一步视为通用冷缓存备份遗漏已修复。
