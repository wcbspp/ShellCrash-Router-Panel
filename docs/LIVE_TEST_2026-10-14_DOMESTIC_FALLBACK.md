# 国内 IP 兜底与规则维护

这次修复补充国内地址分类，不替换用户订阅，也不重新选择节点。仓库仍私有，全量验收未完成，不能发布。

## 原因和顺序

K2P 的订阅使用原生 GeoIP 规则集。对一个地址的固件 `rule-set match` 测试没有匹配；反编译后确认缺少相应地址段。相同地址在 ShellCrash 的国内表中。这不是仅看网页标签得出的结论。

原适配为让自定义域名规则和订阅规则进入内核，移除了 ShellCrash 的国内 IP 提前绕过。但原生导入没有补入同一份国内表，订阅数据遗漏的国内地址便落到了默认代理。需要把绕过优化与内核分流分开处理。

现在按以下顺序处理：

1. 内网、安全例外与直连/全局模式。
2. 用户自定义域名分流。
3. 订阅模板的明确规则。
4. ShellCrash 国内 IPv4 表兜底直连。
5. 默认代理出口。

模板里明确指定的规则继续优先。如果某个国内域名被用户指定代理，它不应被防火墙提前放行。

## 两种实现

- K2P：从已验证的本地国内表生成约 75 KB 的运行时 source rule-set；插入到默认出口之前。保留原配置文件、DNS、策略组和节点。重启从本地表重建，无额外常驻进程。
- AX5：Mihomo 完整模板增加本地 `ipcidr/text` provider，直接读取已有国内表。在 MATCH 之前插入兜底，保留模板规则顺序。没有下载第二份全国数据库。

两机都保留原来的原生 GeoIP/GeoSite 规则。兜底不是“只有名单里的网站能代理”，也不是保证域名的所有服务器都在某一地区；它修补默认出口前的国内 IPv4 分类。

## 真实新连接结果

通过各路由器现有 mixed 入站建立新的 TCP 连接，读取实际连接规则和出口：

| 测试 | AX5 | K2P |
|---|---|---|
| 原遗漏地址 | 原模板自身的国内 IPCIDR 已能直连，新增兜底不是这条连接的命中规则 | 命中 panel-cn-ip，DIRECT |
| 另一个国内地址 | 国内 IPCIDR，DIRECT | 原生国内 rule-set，direct |
| 国外对照地址 | MATCH，台湾节点 | final，台湾节点 |

这是真实内核路由结果，但通过 SSH 转发访问 mixed 入站，不冒充 Wi-Fi TCP/UDP 全场景验收。游戏服务器归属及用户体感改善仍未确认。

## 更新按钮

“更新国内 IP 表”更新 ShellCrash 本地 IPv4 表；不更新订阅 GeoIP/GeoSite，不替换策略组。

AX5 原生 Mihomo 配置通过 provider PUT 无感刷新，并读取实际条目数确认。加载或读回失败时恢复旧文件和旧 provider，恢复也失败时明确报告状态待确认，不声称已经回退。桌面真实按钮更新 4309 → 4311，PID 不变。

K2P 更新本地表后，启动生成新兜底。桌面真实按钮更新 4303 → 4311，完成一次必要的内核重启。两机手机按钮更新相同数据也已通过，无再次重启。网络失败、保护及完整边界路径仍需继续，不能从这几次成功推断全部通过。

## 启动失败与恢复

第一次 K2P 应用失败，服务短暂停止。复用的运行内核依赖控制进程持有文件描述符；旧 manual-stop 标记使延迟启动的 readiness 等待提前结束，控制进程退出后复用链接失效，后续下载解包失败。没有用远端配置备份覆盖设备。

恢复使用与安装记录校验值一致的内核包，原订阅/DNS/分流保留；重新启动后真实路由验证通过。启动逻辑现在在授权启动的后台派发前清除旧停止标记，新产生的用户停止标记仍取消等待。之后真实规则更新成功走完复用内核的启动链路；离线回归覆盖旧标记、超时及后续取消。

## 流量与绕过

首页“内核实时 / 累计（含直连）”统计进入内核的流量，包括代理、DIRECT 与内核测试；完全绕过内核的不计入。这不是服务商订阅消耗，也不是整个 WAN 总量。

ShellCrash 原生支持国内 IP 防火墙绕过；它是降低处理开销的优化。当前有自定义或完整订阅时先进入内核判断，不能把此 DIRECT 兜底写成已恢复所有国内 IP 提前绕过。后续如增加绕过开关，需要同时设计域名/IP 例外，并测试它不破坏明确分流。

实现依据：[sing-box 路由规则](https://sing-box.sagernet.org/configuration/route/rule/)、[Mihomo 规则集](https://wiki.metacubex.one/config/rule-providers/)。固件匹配、内核路由与更新证据保存在私有工作目录，不进入仓库。
