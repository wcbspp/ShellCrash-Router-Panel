# AX5 转换下载恢复验证（2026-10-13）

现象：转换接口的 curl 直连与混合端口代理预检均超时；原服务商独立直取能成功。`--noproxy` 只跳过 curl 的代理设置，仍会进入路由器 OUTPUT 透明代理。

修正：AX5 转换预检和 ShellCrash 生成的转换下载 URL 使用独立 DNS、按目标 IP/端口限定的临时 root TCP 绕过。预检不携带订阅地址，接受可达的 HTTP 400/422；第三方 503 仍拒绝。下载仍由 ShellCrash 生成请求，保持原模板、User-Agent 和换服务开关。没有停止内核、切换全局模式或恢复远程备份。

实机结果：隔离 RAM 工作目录读取本次用户请求参数。第一个服务直连返回 503，代理超时；第二个服务直连预检返回 400，随后转换下载成功，候选文件 756355 字节。运行配置 MD5 校验不变，内核 PID 不变，临时绕过规则数量归零。候选仅下载，没有导入、重启或替换订阅配置；不能据此声称完整加载与实际域名分流通过。

两份脚本已原子替换到 AX5 并逐字节回读，修改前脚本保存在工作目录私密备份。K2P 未改动。已发布的私有 rc.1 资产未替换。

回归：根目录 33 项 Python 测试通过，AX5 46 项 Python 与 14 个 JS 测试脚本通过；构建和迁移基线检查通过。增加代理失效时独立转换恢复、直取不访问转换接口、400 预检语义、两次失败清理等测试。首次根测试在意图差异记录更新前失败；补齐明确变更记录后完整重跑通过。
