# AX5 开机公网回补：实际下载边界

审计发现 `recover-core.sh` 的公网兜底仅依赖旧 curl 的 `--max-filesize`，未声明响应长度时可能继续占用 RAM。新增实际管道截断、生产者退出码和落盘字节数检查；只有安装记录指定 SHA 一致时才能替换核心包。退出时清理临时归档和状态文件，不修改安装记录。

电脑隔离 HTTP 服务器真实发送无 Content-Length 的响应，测试 shim 去掉 curl 大小选项以模拟旧固件；观察临时文件峰值不超过测试上限加一字节。4 项覆盖精确远端命中不访问公网、远端缺新包时使用精确公网包、旧公网包拒绝及超限响应截断。测试没有运行归档内程序。

AX5 固件另外在独立 `/tmp/sc-bootprobe-*` 中验证当前/旧/超限归档三例，使用本地 file 协议验证实际 shell/curl/hash/tar 组合；测试上限缩小到 64 KiB。该实测不冒充真机 HTTP chunked 或真实新内核冷启动。配置、核心 PID 和 boot ID 前后一致，临时目录已清理。

私有证据在 `work/task-state/native-ip-20261016.private/ax5-boot-bound/`；根套件 106 项通过。真实不同版本升级/冷启动与全量发布门槛仍未完成；K2P 公网下载的相同大小边界也需继续审计，不因这一处修复宣称所有下载均有界。

最终根套件106项、AX5 87 Python + 25 JS通过；K2P运行源码本批未改，沿用56fb10c的197 Python + 27 JS记录。旧恢复测试的假curl仅支持`-o`，首次全套因此失败；现改为与生产管道一致的stdout响应，原错误镜像/保留配置断言未变，完整复测通过。迁移基线原哈希未改，逐项记录新增差异。479源文件对本轮已知凭据扫描0命中。
